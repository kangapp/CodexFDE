# 国家级一流本科课程建设方案（本地建设草案）

状态：本稿为2026-10-04本地基线维护新增的建设草案，依据现有课程大纲、课程蓝图与仓库约束编写；不是历史文件恢复，不代表申报资格或课程认定。培养方案、课程编码、学分学时、专业毕业要求映射、团队与申报批次均待校方确认；教学成效待真实教学采集。

## 建设对象与课程合同

建设主线：用Codex搭建个人AI研发工作台，再通过工作台组织人与AI协同，持续开发FlowERP。最终作品同时包含可复用工作台和持续增长的客户ERP，两者分别有版本、测试和人审来源。16讲标题与四项合同回查[课程大纲](../课程大纲-Codex-FDE行动营-个人研发自动化工作台.md)及[课表](../课表｜Codex%20AI%20工程交付行动营.md)，本稿不另设课时、通过标准或产品功能表。

L01～L04先形成工作台V0并完成首次ERP交付；L05～L08用真实业务反例提升检查可信性；L09～L12控制返工、分工和人工审批；L13～L16验证协作入口、真实反馈、陌生环境及现场新需求。课程目标与专业培养要求的正式对应关系待校方确认。

## 学情与分层支持

入课前依据L00操作任务了解学生能否定位目录、运行命令、阅读差异和保存真实输出；尚无学生分布或基础测评数据，不写人数、比例或达成率。零基础学生提供操作示范、逐级提示和术语解释；有经验学生减少提示并增加条件迁移。学生自行作出范围、授权和接受决定，Codex提供建议及实现支持。提示次数和独立表现分别记录，统一产品与工程通过标准。

## 目标、活动和直接证据

下表沿用[课程蓝图](课程蓝图.md)已有CLO解释；正式教学安排与权重待校方确认。

| 目标 | 学生中心活动 | 可观察证据 |
|---|---|---|
| CLO-1 判断范围与责任 | 比较合法请求、越界请求和替代方案，确认授权 | 首次判断、来源、修订理由与授权范围 |
| CLO-2 把要求变成可验收约定 | 与Codex澄清需求，经同伴反证修订Spec | 初稿、歧义、确认稿与验收项映射 |
| CLO-3 判断检查能否发现错误 | 预测反例，再核对正常和失败后的真实状态 | 输入、预期、实际结果、退出码、来源及业务状态 |
| CLO-4 控制修复与停止 | 从可信失败选择最小写集，决定继续或停止 | 允许范围、执行轮次、剩余失败与停止依据 |
| CLO-5 组织分工与人工审核 | 分析依赖和冲突，安排复验、打回及具名接受 | 原始子报告、集成复验、状态转换和人审记录 |
| CLO-6 运行、交付与改进系统 | 在新环境换条件或交付未实现的小需求 | 新输入、实际执行、独立迁移说明和剩余风险 |

## 混合式教学与挑战设计

线上精讲原则上不超过30分钟，讲问题框架、核心概念与关键示范；线下行动课或课后项目完成故障实验、同伴反证、修订与迁移，不照抄线上操作。每讲先回答Codex怎样协作，再说明ERP产品增量、它暴露的工程问题、工作台能力与学生独立迁移证据。挑战来自版本、权限、数据状态和失败传播的真实矛盾，不以代码行数或术语数量代替。

采用“首次判断—实现—失败—修订—同伴反馈—换条件迁移”的活动链。高阶性体现在学生解释因果与权衡；创新性体现在以受控人与AI协作解决现场需求；挑战度体现在面对反例、故障和陌生环境仍能保留证据并作判断。这些是教学设计意图，尚不构成教学效果证明。

## 形成性评价和职责分离

工程结果核对同一候选的输入、退出码、报告、业务状态与源码指纹；学习结果另看学生能否独立解释和迁移，记录“可独立、需提示、尚未达成”。保留首次判断、失败、修订前后版本及具名反馈。教学模拟、参考仓库绿灯、AI自述或满意度不能替代学生本人学习证据。

工程诚信、规则意识和协作责任落实到不伪造失败或接受、不越权修改、不以技术通过代替采购审批和具名验收、保护数据与凭据等实际决定中。涉及服务国家数字化的教学讨论须回到真实问题与可验证贡献，不另贴口号。

## 持续改进与证据建设

计划按CLO汇总首次与二次提交变化、关键误区、提示次数、迁移表现和不同起点学生增值；这些数据待真实教学采集。每次改进保留问题来源、材料版本、采取的改法和复查结果，再在后续教学周期检查是否有效。平均分、满意度或单次运行通过不能单独证明教学成效。

校方需确认培养方案、课程编码、学分学时、两个实际教学周期、学生记录与作品授权、教学效果、同行评价、团队资格、政治审查、知识产权及五年建设计划。当前均按待校方确认或待建设管理，不用生成文案或模拟数据补位。正式使用前由学校核对当批次官方文件并记录来源与日期，本稿不提供当前申报政策结论。

材料核对流程见[申报级质量门](国家级一流本科课程申报级质量门.md)；学生操作入口仍为[学生总入口](../README.md)。
